The Birthday Paradox: A Two-Page Note

A. Example and B. Sample
Example Institute of Elementary Probability · demo document for annotated-study-sheets
Abstract How many people must be in a room before two of them are more likely than not to share a birthday? The answer, 23, surprises almost everyone because intuition compares one person with all the others, while the relevant count is the number of pairs, which grows quadratically. We derive the exact probability, give the standard approximation p(n) ≈ 1 − exp(−n2/730), check it by simulation and discuss why the same effect governs hash collisions in computer science.

1. Introduction

The birthday problem asks for the probability that, in a group of n people, at least two share a birthday. It is called a paradox not because it is contradictory but because the answer is far smaller than people guess: most estimates for a 50% chance lie between 100 and 183, half of 365 days. The true value is 23.

The mistake is to think about one particular person. With 23 people there are 22 others for each of them, which feels like few, but there are 23 × 22 / 2 = 253 different pairs, and any one of them can produce the match.

2. Exact probability

Assume 365 equally likely birthdays and independent people. It is easier to compute the complement, the probability that all n birthdays are different. The first person can have any day, the second must avoid one day, the third two days, and so on:

q(n) = (365/365) · (364/365) · … · ((365 − n + 1)/365)(1)

The probability of at least one shared birthday is then p(n) = 1 − q(n). Table 1 lists a few values.

3. An approximation

Using 1 − x ≈ e−x for small x on every factor of (1) and summing the exponents gives

p(n) ≈ 1 − exp(−n(n − 1) / 730) ≈ 1 − exp(−n² / 730)(2)

The exponent is the expected number of matching pairs, n(n − 1)/2 divided by 365. Setting p = 1/2 gives n ≈ √(730 ln 2) ≈ 22.5, which rounds up to 23.

4. Simulation

We drew 100,000 random groups of 23 birthdays and counted the groups with at least one repeated day. The empirical frequency was 0.510 (seed 23), in agreement with Table 1. Real birthdays are not uniform: more births fall in some months. Non-uniformity can only increase the collision probability, so 23 is an upper bound for real populations.

5. Hash collisions

The same arithmetic explains why a hash with d possible values starts to collide after about √d items, not d/2. For a 64-bit hash, collisions become likely after roughly 232 ≈ 4 × 109 items. This “birthday bound” sets the security of many cryptographic constructions.

6. Conclusion

The birthday paradox is a counting lesson: when every pair can produce an event, the number of chances grows with n2. Thinking in pairs turns a surprising number into an obvious one.
